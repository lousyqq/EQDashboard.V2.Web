# EQ Performance Dashboard — 專案架構說明 (專案架構.md)

> 本文件描述 **EQDashboard.V2.Web**（重構版、目前主線）的完整目錄結構與各檔案職責。
> 用途：UMC（聯電）廠區效能看板入口 — 依使用者權限/廠區顯示可存取的看板連結，並提供帳號/權限/看板的後台管理。
> 技術定位、開發規範與安全現況請對照 `CLAUDE.md`；歷史決策與踩坑紀錄請對照 `memory.md`。
> 最後更新：2026-06-07。

---

## 1. 專案概觀

| 項目 | 說明 |
| --- | --- |
| 框架 | ASP.NET Core 9.0 MVC + Static Files（Kestrel / IIS）|
| 資料存取 | EF Core 9 + 原生 ADO.NET（`Microsoft.Data.SqlClient`）|
| 資料庫 | MSSQL（Server `Sariel`，Catalog `EQDashboardV2`，User `testuser`）|
| 前端 | 純 ES Modules（無 bundler）＋ jQuery + Bootstrap 5 + DataTables（全走 CDN）|
| 身份驗證 | 雙模式：Windows Negotiate 自動偵測 + AD LDAP 手動帳密 |
| Schema 管理 | **無 EF Migrations**；由 `SchemaBootstrap` 啟動時 idempotent raw SQL 自我修復 |
| 資料保存 | CRUD 異動自動靜默寫回 MSSQL（無「同步至 DB」按鈕）|

> 另有舊版 **EQDashboard**（單一專案、JS/CSS 單檔），僅作參考，非主線。兩版版面與功能 100% 一致。

## 3. 後端檔案逐一說明

### 3.1 進入點與設定

| 檔案 | 職責 |
| --- | --- |
| `Program.cs` | 應用組裝中樞：註冊 DI（所有 Service/DbContext/MemoryCache/Antiforgery/ResponseCompression/RateLimiter/Negotiate）、設定 middleware pipeline（驗證→授權→ActivityLogging→StaticFiles→MVC）、啟動時呼叫 `SchemaBootstrap` 與 `MigrateBase64IconsAsync`、定義 `/health` 與 `/health/ready` 健康檢查端點。|
| `EQDashboard.V2.Web.csproj` | 目標 .NET 9；`Nullable`/`ImplicitUsings` 皆 enable；NuGet 套件（EF Core 9、Microsoft.Data.SqlClient、Swashbuckle 等）。|
| `web.config` | IIS 部署用；設定 AspNetCoreModuleV2 與 Windows 驗證（修過 500.19）。|
| `appsettings*.json` | 連線字串 key 一律 `ConnectionStrings:EQDashboard`（可用環境變數 `ConnectionStrings__EQDashboard` 覆寫）；`Auth` 區塊含 LDAP 設定與離線開發用 `TestAccounts`（正式環境須關閉）。|
| `Properties/launchSettings.json` | 本機啟動 profile 與連接埠。|
| `package.json` / `package-lock.json` | 開發輔助（前端走 CDN，**非** build pipeline）。|

### 3.2 Controllers/（10 個，皆 `[ApiController]`，DTO 定義於各檔末尾）

| 檔案 | 路由 / 職責 | 授權 |
| --- | --- | --- |
| `SettingsController.cs` | Legacy 全量 API：`GetInitialData`（一次取全部表，非 admin 後端按可見性 `FilterTable` 列級過濾）、`SaveData`（全量 DELETE→INSERT 包交易，僅 Excel 匯入用）、`UpdateLoginStats`。支援 ETag/304。|混合（GetInitialData 寬鬆、SaveData admin）|
| `AccountsController.cs` | 帳號 CRUD（委派 `IAccountService`）；刪除帶 soft-delete backup + 稽核。DTO：`AccountFullDto`。| `[Authorize(Roles="admin")]` |
| `MenusController.cs` | 看板 CRUD + 批次（`BatchUpdateMenus`/`BatchDeleteMenus`，拖曳排序走此）；逐節點 `IMenuAuthService` 權限檢查。| `[Authorize]`（逐節點檢查）|
| `RolesController.cs` | 權限群組 CRUD + `Map_Role_Menu` 維護（寫入前驗 `AllowedMenuIds` 存在）。DTO：`RoleDto`。| `[Authorize(Roles="admin")]` |
| `FabsController.cs` | 廠區 CRUD + `Map_Fab_Role` 維護（寫入前驗 `AssignedRoles` 存在）。| `[Authorize(Roles="admin")]` |
| `AppsController.cs` | App 卡片 CRUD（圖示走 `IIconStorageService`）。| `[Authorize]`（逐節點檢查）|
| `AuthController.cs` | 登入流程：`WhoAmI`（Negotiate-challenge 偵測，擋未註冊不發 cookie）、LDAP 手動登入、登出、`CsrfToken` 核發。取 EmpId 走 `ClaimTypes.NameIdentifier`。| 寬鬆 baseline |
| `RequestsController.cs` | 申請單 CRUD（IDOR 防護：一般使用者只動自己的）。| `[Authorize]` |
| `PersonalSettingsController.cs` | 個人版面（上方導覽列）per-user delete+insert；強制 claim EmpId。| `[Authorize]` |
| `ActivityLogsController.cs` | 操作紀錄查詢（分頁）+ 清除。| `[Authorize(Roles="admin")]` |

### 3.3 Services/ + Services/Interfaces/

| 檔案 | 職責 |
| --- | --- |
| `SettingsService.cs` (`ISettingsService`) | 讀寫核心：`GetInitialDataAsync`（雙層 `IMemoryCache` — Global 60s / Volatile 10s，全部表載入成功才寫快取）、`SaveDataAsync`（全量覆寫包交易，FK 用 `WITH CHECK CHECK` 重驗、失敗 rollback）、`InvalidateInitialDataCache`/`InvalidateVolatileDataCache`（**雙重 load-bearing**：清快取 + bump 靜態 `_currentETag`）、`GetCurrentETag`。`TableNames` 為全量覆寫表清單（**不含** PersonalSettings）。|
| `AccountService.cs` (`IAccountService`) | 帳號 CRUD 邏輯：建/改/刪帳號與其 Role/委派/ACL mappings；刪除產生 soft-delete backup；每個寫入後 Invalidate（bump ETag）。|
| `AuthService.cs` (`IAuthService`) | 驗證邏輯：LDAP 帳密驗證、`TestAccounts` 比對；用 `IOptionsSnapshot<AuthSettings>`。|
| `MenuAuthService.cs` (`IMenuAuthService`) | 權限核心：`GetVisibleMenuIdsAsync`（可見看板集合，以 `visibleMenus:{ETag}:{empId}` 跨請求快取、回傳防禦性副本）、逐節點編輯權限檢查（走 `Map_Menu_Structure` parent chain）。優先序 **Menu ACL > Account override > Role**。Scoped。|
| `IconStorageService.cs` (`IIconStorageService`) | 圖示存實體檔：`SaveAsync`（data: URI 依 MIME 白名單寫檔回路徑、URL 正規化、FA class 原樣）、`DeleteIfLocalUnreferencedAsync`（孤兒清理 + path-traversal 防護）、`MigrateBase64IconsAsync`（啟動一次性轉舊 base64）。|
| `SchemaBootstrap.cs` (`ISchemaBootstrap`) | 啟動時 idempotent raw SQL 自我修復 schema：補表/補欄位/補索引。**所有索引集中於 `EnsureIndexesAsync`**（`IF NOT EXISTS(sys.indexes) CREATE INDEX`）。|
| `ActivityLogger.cs` (`IActivityLogger`) | 稽核寫入入口：`LogAuditAsync`（組裝 `UserActivityLog` 丟入佇列）。|
| `ActivityLogQueue.cs` | Singleton `Channel<UserActivityLog>`；`FullMode=Wait`+`TryWrite` 非阻塞，滿載記 Warning **不丟最舊**；提供 `TryDequeue` 供批次 drain。|
| `ActivityLogProcessor.cs` | `BackgroundService`：`DequeueAsync` 等第一筆 + `TryDequeue` drain 成批（≤100）→ `AddRange` + 單次 `SaveChanges`；批次失敗退回逐筆隔離毒資料；每工作單位 `CreateScope()` 解析 Scoped DbContext。|

> Interfaces/ 下對應 7 個介面：`ISettingsService`/`IAccountService`/`IAuthService`/`IMenuAuthService`/`IIconStorageService`/`ISchemaBootstrap`/`IActivityLogger`。

## 5. 關鍵跨檔機制（速查）

- **請求流程**：瀏覽器 → `api.js`（補 CSRF/XHR 標頭）→ Controller → Service → `AppDbContext`/raw SQL → MSSQL。回應經 `GetInitialData` 快取（含 ETag/304）。
- **快取與 ETag**：`SettingsService` 雙層快取（Global 60s / Volatile 10s）；靜態 `_currentETag` 由任何 `Invalidate*DataCache()` bump，同時作廢 `MenuAuthService` 的 `visibleMenus:{ETag}:{empId}` 可見集合快取。**任何新增的權限相關寫入路徑都必須呼叫 Invalidate**。
- **權限判定**：後端 `MenuAuthService`（優先序 Menu ACL > Account override > Role，走 parent chain）；前端 `getMenuPermissions` 對齊。非 admin 的 `GetInitialData`/`GetMenus` 一律後端列級過濾。
- **圖示儲存**：一律 base64 → 實體檔，DB 只存 `/images/icons/{guid}.{ext}`，統一走 `IIconStorageService`。
- **稽核**：Middleware → `ActivityLogQueue`（Channel）→ `ActivityLogProcessor`（批次寫入）。
- **個人版面**：per-user 走 `/api/PersonalSettings`；localStorage 只快取「登入者自己」一份且每次以 DB 為準覆寫。
- **Schema**：無 EF Migrations，啟動時 `SchemaBootstrap` idempotent 修復；索引集中 `EnsureIndexesAsync`。
